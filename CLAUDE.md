# go-sdl3 (wasm fork) — notes for Claude

Pure-Go SDL3 bindings (no CGo). Native platforms link the SDL3 dynamic library
at runtime via `ebitengine/purego` (`*_functions.gen_impl.go`, build tag `!js`).
The browser/WebAssembly target instead calls an Emscripten-compiled SDL3 module
through `syscall/js` (`*_functions_js.go`, build tag `js`).

This fork of [Zyko0/go-sdl3](https://github.com/Zyko0/go-sdl3) adds the browser
(`js`/`wasm`) target. Work happens on the **`wasm-render-fixes`** branch (the
former parallel branch `wasm-support` was merged into it — see history note at
the end). The module path is still `github.com/Zyko0/go-sdl3`, so a downstream
filesystem `replace github.com/Zyko0/go-sdl3 => ../go-sdl3-wasm` is seamless.

## Architecture

- SDL3 + SDL3_image + SDL3_ttf + SDL3_mixer (with OGG/FLAC/MP3/MIDI decoders and
  a Web Audio backend) are compiled to a single Emscripten module:
  `cmd/wasmsdl/assets/{sdl.js,sdl.wasm}`. Exports are `_SDL_*`, `_IMG_*`,
  `_TTF_*`, `_MIX_*` (grep `sdl.js` / `strings sdl.wasm`). The build recipe is
  `.docker/emscripten-build/Dockerfile`; when relinking, force-link the static
  archives (`-Wl,--whole-archive`) or `EXPORT_ALL` drops unreferenced symbols.
- `cmd/wasmsdl` builds the user program with `GOOS=js GOARCH=wasm` and bundles
  it with `index.html`, `wasm_exec.js`, and the prebuilt module. Run with
  `go run ./cmd/wasmsdl serve ./path/to/app`.
- Go bindings for js live in `*/*_functions_js.go` as `iXxx` closures that
  marshal args and call `js.Global().Get("Module").Call("_SDL_Xxx", ...)`.
- The program's frame loop must go through `sdl.RunLoop`. On js it paces
  iterations with `requestAnimationFrame` but runs the callback **on the
  goroutine that called RunLoop** (the main goroutine), NOT via
  `emscripten_set_main_loop`. Rule learned the hard way: user code that
  *blocks* (sleep/channel waits) inside a `js.FuncOf` callback pins the tab's
  main thread inside the Go scheduler (`findRunnable` never pauses back to the
  event loop), while the same blocking code on the main goroutine pauses
  cleanly. So JS callbacks must only signal channels; all user code runs on
  Go-owned goroutines. (Also: a hand-written `for { PollEvent; SDL_Delay }`
  loop freezes the tab — `SDL_Delay` is a no-op on js; use `time.Sleep`.)
- The js bindings are generated by `cmd/jsgen`, which emits
  `panic("not implemented on js")` as the first line of every function. A
  function only works once that panic is removed and its argument/return
  marshaling is verified. Many functions are still stubbed.

## Root-cause bugs (fixed) that blocked all browser rendering

1. **Canvas had no size → 0×0 window → nothing rendered.** SDL3's Emscripten
   backend uses the canvas CSS layout size (`getBoundingClientRect`) as the
   window size. Fixes: `sizeCanvas(w, h)` in `sdl/glue_js.go` (called before the
   SDL call in `iCreateWindow` / `iCreateWindowAndRenderer`), and a rewritten
   `cmd/wasmsdl/assets/index.html` whose canvas no longer collapses.
2. **`sdl.RunLoop` passed fps `-1`** to `emscripten_set_main_loop`; changed to
   `0` so emscripten uses `requestAnimationFrame` (`sdl/init_js.go`).
3. **`cmd/wasmsdl` couldn't find `wasm_exec.js`** under `go run` (only checked
   the `GOROOT` env var); added a fallback to `go env GOROOT`.

## Un-stubbing bindings — rules learned the hard way

Enabling a binding is usually just deleting the leading `panic`, **but audit the
body** — the generator has real bugs. Helpers live in `internal/` (js-tagged).

- **Opaque handles** (`*Renderer`, `*Texture`, `*Window`, `*Mixer`, `*Track` —
  all zero-size Go structs): `internal.GetJSPointer(obj)`; created via
  `internal.NewObject`.
- **Input struct / nilable pointer** (e.g. `*sdl.AudioSpec`, `*FRect`, `*Color`):
  `internal.CloneObjectToJSStack(ptr)` — returns `js.Null()` (→ NULL) for nil
  and copies the struct otherwise. Do **not** use the GetJSPointer-or-StackAlloc
  pattern for input structs: it passes a pointer to uninitialised memory (this
  silently broke `MIX_CreateMixerDevice(_, nil)`).
- **Small struct passed by value in the C API** (e.g. `SDL_Color`): the wasm ABI
  lowers it to a pointer arg — `internal.StackAlloc(4)` +
  `internal.SetValue(ptr, js.ValueOf(int32(packed)), "i32")`, pass the pointer
  (model: `ttf` `iRenderText_Blended`). Passing the packed value directly causes
  "memory access out of bounds".
- **Scalar `float32`**: pass it **directly**. The generator sometimes emits
  `int32(x)`, which truncates (broke `MIX_SetTrackGain`, `SetRenderScale`).
  `cmd/jsgen` now generates floats correctly, so new stubs won't regress.
- **`int64`/64-bit flags**: `internal.NewBigInt(x)`. `int32`/`uint32`: direct.
  But `size_t` string lengths are `i32` on wasm32 — `NewBigInt` truncated them.
- **u64/i64 *returns*** (e.g. `SDL_GetWindowFlags`, `SDL_GetTicksNS`) arrive as
  BigInt; `js.Value.Int()` panics on BigInt — use `internal.GetInt64(ret)`
  (it stringifies, so it handles both Number and BigInt).
- **Scalar out-param**: `internal.StackAlloc(4)` then
  `internal.GetValue(ptr, "i32"|"float")` (model: `iGetWindowSize`).
- **Handle return**: `internal.NewObject[T](ret)` — it returns `nil` for a NULL
  C pointer (matching native bindings), so failed calls surface through the Go
  methods' `if x == nil` guards. Don't re-check the raw pointer.
- **Byte buffers across the module boundary**: `internal.CloneByteSliceToJSHeap`
  (Go's wasm memory and the Emscripten heap are separate address spaces).
- **SDL-allocated output buffers** (template: `LoadWAV_IO`): platform-split the
  wrapper (`loadwav_notjs.go` / `loadwav_js.go`). The js version copies the
  buffer out of the wasm heap (`GetByteSliceFromJSPtr`) and frees it with
  `_SDL_free`; the native path's `ClonePtrSlice` + `internal.Free` assume a
  Go-readable pointer and panic on js. Path-based variants (`LoadWAV`) are
  unsupported on js — use the `_IO` variant with `IOFromConstMem`.
- Some func pointers are declared in `*_functions.gen.go` but never assigned in
  the js file (e.g. `iSetTrackLoops`) → nil func → panic. Write them by hand.
- **HEAPU8 must be fetched fresh every use** — `internal.heap()` does this.
  Emscripten rebinds the global `HEAPU8` on memory growth, detaching the old
  typed array; a cached view throws "detached ArrayBuffer".

## Timestamps in the browser

`cmd/wasmsdl/assets/sdl.js` is **patched** (and the Dockerfile re-applies the
patch on rebuild): `_emscripten_date_now` returns
`performance.timeOrigin + performance.now()` instead of `Date.now()`. Without
it every SDL timestamp — `SDL_GetTicksNS` *and* input-event timestamps — is
quantized to 1 ms, because SDL3's `SDL_GetPerformanceCounter` probes
`CLOCK_MONOTONIC_RAW` (id 4), Emscripten's C-side WASI shim rejects ids > 3,
and SDL falls back to `gettimeofday`, which Emscripten's libc implements with
`emscripten_date_now`. Measured resolution after the patch (headless Chrome):
~100 µs normally, ~5 µs when the page is cross-origin isolated — `wasmsdl
serve` sends COOP/COEP headers to enable that. The clean upstream fix would be
SDL not selecting `CLOCK_MONOTONIC_RAW` on Emscripten. Go's `time.Now()` on js
still has 1 ms resolution (wall clock = `Date.now()`) — use SDL timestamps for
timing.

## Assets in the browser

There is no real filesystem, so path-based loaders won't work without Emscripten
FS preloading. The portable approach (works native and web) is `go:embed` the
bytes → `sdl.IOFromConstMem(bytes)` → `img.LoadTextureIO` / `ttf.OpenFontIO`.
`IOFromConstMem` already copies the bytes into the Emscripten heap.

## Verification examples

- `examples/wasmcheck` — 2D render path (points, primitives, render-target
  texture with modulation, out-param read-back).
- `examples/imgttf` — SDL3_image (runtime-generated PNG) and SDL3_ttf
  (embedded-font text), both via in-memory IOStreams.
- `examples/audio` — core SDL audio: builds a WAV in memory, decodes with
  `LoadWAV_IO`, queues PCM on click/keypress (browsers gate audio behind a
  user gesture).

The main downstream consumer is `~/00_git/goxpyriment` (filesystem `replace`).
Its `hello_world` runs the full experiment-startup path — SDL/TTF init,
in-memory font loading, system/display info, text rendering — and renders in
the browser (verified 2026-07-13). Its `cmd/gen-wasm-exports` prints which
go-sdl3 calls it uses that are still stubbed here.

Verify in a browser (`go run ./cmd/wasmsdl serve ./examples/<x>`); each
remaining stub panics in the JS console with its symbol name, which tells you
what to un-stub next. Headless check: `google-chrome --headless=new
--use-gl=swiftshader --no-sandbox` (add
`--autoplay-policy=no-user-gesture-required` for audio), drive via CDP. Audio
liveness: `Module.SDL3.audioContext.state`; a track's
`MIX_GetTrackPlaybackPosition` advancing = real playback.
